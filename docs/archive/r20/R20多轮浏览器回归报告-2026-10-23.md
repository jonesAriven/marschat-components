## 2 各维度明细

### 2.1 A · SSO 免登（3 轮 × 6 应用，225/225）

每轮从不同应用进入（R1 portal / R2 kb-ops / R3 infra），硬断言「**整轮口令输入次数 == 1**」：

- 入口应用：点「统一认证登录（SSO）」→ IdP `login.html` → `Input.insertText` 填 admin → 提交 → 回落地页；
- 其余 5 应用：直接导航入口，**免登直落业务页**（无密码框 + URL 不含 `/login` + 业务特征词命中 ≥2）；
- 每个应用另核：OIDC 全链（回调带 `code` + 换票 200）· 落地路径符合 `apps-registry` · 有会话态 ·
  **已登录态重载仍直落业务页**（会话保持）· D 组（5xx=0 / CORS=0 / loadingFailed=0 / 4xx=0 /
  app-kit 告警=0 / `app-config.json` 200 / 权限探针**同源**）。

**结果**：3 轮 `pwd_prompts` 均 == 1；225 断言全绿。分布：portal 38 · kb-web 36 · kb-ops 38 ·
infra 38 · cosmic 36 · activecode 36 · 汇总 3（与 R19 逐应用一致）。

### 2.2 B · 独立账密登录（2 轮 × 5 应用，170/170）

portal / kb-web / infra / cosmic / activecode 各有本地账密入口；kb-ops 按设计无本地入口。
断言含：有入口 → 登录进业务页 → 落地路径 → 会话态 → **未误跳 IdP** → 口令输入 1 次 →
登录 POST 走本应用同源后端 → **已登录态重载不被踢**（坑 #47 回归位）。

**首轮 168/170**：2 条 FAIL 全部落在 kb-ops 的「错密返 401」断言（§3.1），订正后复跑 **170/170**。

## 3 缺陷与订正

### 3.1 【测试断言订正·已回写】B 维度 kb-ops 错密口径（R19 §3.4 的正式落地）

R19 已定性「kb-ops `/ops-api/auth/login` 错密返 `200 + code:400` 属 R15 已加 nginx 路由后的
**用例前提过期**，产品行为正确（拒绝、不落会话、文案一致）」，但**脚本回写未完成**（R19 报告
§3.4 称「断言作废」实际未改）。本轮正式订正 `r20_b.py`：

```python
# 订正后：语义拒绝 = 401 或 200+code:400（T-LOW-27 跨应用状态码不统一的已知取舍）
rejected = (st == 401) or (st == 200 and '"code":400' in body)
```

订正后复跑 **170/170**。`T-LOW-27`（错密传输层状态码跨应用不统一）维持**待拍板**不变。

### 3.2 【测试抖动·已复跑】H2 infra 首轮 ConnectionClosedError

首轮 H2 infra 在「注入垃圾 token → 整页重载」后 CDP 连接关闭（`ConnectionClosedError`），
后续自愈断言未能执行。与 R19 §3.6 同型（导航/重载后未等够渲染 + 连接被回收）。
**单点复跑 6/6 PASS**（自动恢复回业务页、垃圾 token 不残留；恢复窗口内的 401 为测试自造，见 R19 §4.2 注）。

### 3.3 【无产品缺陷】

本轮七维度 + 组件侧复验**未发现新的产品缺陷**。R19 修复的三项（app-kit 0.1.9 无票不探 /
脚手架补全 + 自检门禁 / `.npmrc` 脱敏）经 H1、门禁双向验证、单测逐一确认**仍在生效**。
