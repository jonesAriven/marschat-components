## 3. 简报数据勘误（🔴 重要）

R11 任务简报中 **2 个应用入口域名为 team-lead 凭印象填写，与配置真源不符**。我已用 `devtools/apps-registry.yml` 逐行核对：

| 应用 | 简报值（❌） | 真源值（✅，`apps-registry.yml`） |
|---|---|---|
| activecode | ~~`https://code.marschat.online/activecode/`~~ | **`https://tools.marschat.online/activecode/`**（第 125 行 `entry:`；第 117 行 redirect-uri 亦为该域） |
| kb-ops | ~~`https://ops.marschat.online/ops/`~~ | **`https://kb.marschat.online/ops/`**（第 73 行 `entry:`） |

其余四应用与真源一致（portal 第 35 行、kb-web 第 56 行、infra 第 97 行、cosmic 第 156 行）。

**处置**：
1. `ENTRY/R1`、`ENTRY/R2` 两条 FAIL（`code.marschat.online/activecode/main.html` 404）**重分类为「简报数据错误（team-lead 提供）」，不计入产品缺陷**。测试执行本身正确（curl 与 headless 两轮均 404，是该域名未挂 `/activecode` 路由）。
2. activecode 的 B / C / F 已按真源入口 `tools.marschat.online/activecode/` 重跑，全部 PASS（见 §2）。
3. A 维度 kb-ops 经核实用的是真源 `kb.marschat.online/ops/` ✅（无需重跑）。

**方法论沉淀（写入 QA 用例规范）**：
> **断言用的入口 URL 必须从配置真源 `devtools/apps-registry.yml` 的 `frontend.entry` 取，不得从任务简报、上轮报告或他人转述转抄。** 开测前先做一次「入口契约探针」（本轮 `r11_0_ingress.py`），把每个入口的 `http_code / redirect / remote_ip / time_total` 落盘，异常先与真源对齐再判缺陷。

其余三条教训（本轮实际踩到）：
- **DOM 判据必须限定目标容器子树**：统计「可编辑控件」时若用 `document` 全页取，会把查询区/分页控件计入（详见 §4 假阳性 ②）。
- **产物符号计数不能判依赖版本**：`resolvePermissionsIssuer` / `runtimeConfigCandidates` 是函数名，生产 bundle 会被 mangling；必须用源码锁 + 运行时行为（详见 §5 T-ENG-12）。
- **先读 README 的网关约定再写判据**：infra 的 nginx `location /infra/api/` → `proxy_pass .../infra/` 会剥一层 `/api`，双前缀是正确实现（坑 #26），不是缺陷。
