> **范围**：在 mykng 用 **headless chromium + CDP**（不占用良哥本机前台浏览器）对 6 应用做**多轮、多维度**回归：

> **凭据**：本文不含任何口令 / secret 明文，一律见 Vaultwarden（`vault.marschat.online`）或 infrastructure-map 技能。

## 3. 本轮修复的真实缺陷

### 3.1 🔴 D2（高危）· 应用本地「修改密码」真的改本地影子口令 → 身份分裂

**复现（浏览器实测，portal）**：

1. 独立账密登录 portal → 展开右上角用户下拉 → 点「修改密码」
2. 填入旧口令 / 新口令 / 确认 → 点「确定」
3. 结果：`POST /portal/api/auth/change-password` → **HTTP 200 `{"code":200,"message":"success"}`**，弹窗关闭、无任何报错
4. 但改的是**本地影子表 `tools.sys_user.password`**（bcrypt），**中心 `marschat_auth.user` 口令纹丝不动**

> 佐证：改密后立即用新口令打中心 `/auth/login` → 仍是新口令；用旧口令打中心 → 200 可登（即中心没变）。

**危害**：与 Phase 11 硬约束「**口令唯一真源在认证中心，应用本地表降级为影子**」正面冲突。用户以为改了平台口令，实际变成「同一用户名两套口令」——身份分裂后门。activecode 同病（`admin_user` 本地 salt+hash 比对后改密）。

**修复**（提交 `ad356c90`，devtools `dev` 双推）：

| 位置 | 改动 |
|---|---|
| `portal-server/.../AuthController.java#changePassword` | 一律 `throw new BusinessException(410, "口令由统一认证中心统一管理，请通过登录页「忘记密码」或联系平台管理员重置")`，**不再触碰本地表** |
| `active-manager/.../AuthController.java#changePassword` | 返回 `ResponseEntity.status(410 GONE)` + `success:false` + WARN 日志 |
| `portal/src/layouts/MainLayout.vue` | 下拉项「修改密码」→「**重置密码 / 走统一认证**」，直达 `${OIDC_ISSUER}/forgot-password.html`；移除本地改密弹窗与其死代码（`passwordForm` / `passwordRules` / `handlePasswordSubmit` 及 `changePassword` 导入） |

**正确范式（已确认并写入 §5）**：kb-web 的「修改密码」走 `PUT /kb/api/user/password`，由 **kb-gateway `application.yml:86` 的 `/kb/api/user/**` 路由代理到中心**，实测真的改中心口令 —— 这才是其余应用应对齐的实现。

### 3.2 🟡 D3（低危）· `auth.marschat.online/favicon.ico` 403/404

**现象**：六应用 SSO 全程 Console 各带一条 `Failed to load resource: ... 404`。
**定位**：`probe404.py` 抓到真身 = `https://auth.marschat.online/favicon.ico`（浏览器停 IdP 登录页时自动发起）；直连 `http://127.0.0.1:8085/favicon.ico` → **403**（链3 `anyRequest().authenticated()` 挡下），经公网入口回落 404。
**修复**：**三处联动**，缺一处都不生效（这正是「排查必须追到最末端」的典型）：

| # | 位置 | 改动 | 复核 |
|---|---|---|---|
| 1 | auth-center 链3 `SecurityConfig` | 显式 `permitAll("/favicon.ico")` | 直连 8085 → **200** |
| 2 | auth-center `src/main/resources/static/favicon.ico` | 新增 16×16 蓝底白 M（894 B） | jar 内 `BOOT-INF/classes/static/favicon.ico` 894 B 在位 |
| 3 | **边缘 nginx**（config-as-code `hosts/tencent-cloud-2/nginx/sites-available/auth.marschat.online`） | 新增 `location = /favicon.ico` 精确匹配反代 | 公网 → **200 `image/x-icon` 894 B** |

> ⚠️ 只做第 1、2 步时公网仍是 404 —— 该站点末尾是 `location / { return 404; }`（认证中心不承载其他应用），
> 未登记的路径一律被顶回。走 config-as-code 真源：commit → push → `sync/push-to-host.sh tencent-cloud-2`（带 `nginx -t` 门禁 + 失败自动回滚）。
> **禁止**直接 ssh 上机改 `/etc/nginx`。

**影响**：零功能变更，不改变任何鉴权边界（favicon 无敏感信息）。

## 4. 测试脚本误判（登记，避免重踩）

### 4.1 误判 #13 · 把设计内的 SLO 探针当成「跨域违规直连」

- **误报**：5 应用 × 2 轮共 10 条 `FAIL 无跨域直连中心 /auth|/admin`，证据都是 `https://auth.marschat.online/auth/session`。
- **真因**：`/auth/session` 是**会话探针**，auth-center 链2 显式 `permitAll` 并配了带凭据的 CORS —— 各应用 `startSessionWatcher` 靠它做 SLO 登出联动，属设计内行为。
- **纠正**：违规判据收窄为「跨域直连 **`/admin/**`**」或「跨域提交账密 **`/auth/login`**」——前者提权、后者绕 BFF。已改断言。

### 4.2 误判 #14 · 「退出登录」不在 DOM（Element Plus 下拉懒渲染）

- **误报**：R3「登出后各应用仍免登」5 条 FAIL、R4「登出回登录页」4 条 FAIL，看起来像 SLO 全崩。
- **真因**：portal 的「退出登录」在 `el-dropdown-menu` 内，**未展开时不在 DOM**；脚本 `click_btn('退出登录')` 返回 `NO-BUTTON`，登出根本没触发 → 下游断言全部连带失败。
- **纠正**：`do_logout()` 先点 `.user-info / .el-dropdown / .el-avatar` 展开，再点「退出登录」；并把「按钮是否命中」单列一条断言，避免把「没点到」误读成「功能坏了」。

## 5. 沉淀到手册的口径变更

1. **改密唯一正确姿势**：应用侧一律**不得**本地比对/本地改密；要么像 kb-web 那样**经 BFF/网关代理到中心端点**，要么（无代理能力时）**下线入口并引导走中心「忘记密码」**。
2. **探测改密端点有副作用**：`PUT/POST .../password` 是会真改口令的写操作。定位时**必须准备回滚**（本轮即先改后还原，并复核中心登录恢复），禁止在共享账号上裸探。
3. **console 404 先抓 URL 再下结论**：`Log.entryAdded` 只给文本不给 URL，必须配合 `Network.responseReceived` 才能定性（本轮靠它把「六应用都 404」收敛成「同一个 favicon」）。
